# Blog Cover Prompt

把文章的核心关系画成一张可辨识的技术概念封面，而不是给任意题材套上“蓝色科技感”。默认中文沟通，交付一份可直接复制的英文正向提示词及简短负向约束；用户指定语言、模型或格式时从其要求。

## 视觉依据

风格来自 2026-09-19 实际查看的 10 张文章 frontmatter `image` 封面，不包含正文配图或主题默认背景。9 张为 1672×941，1 张为 1280×720，统一接近 16:9。

查看随 skill 保存的 [封面参考拼图](references/cover-style-board.jpg)，将其作为配色、材质、光线和信息密度的视觉锚点。工具无法看图时使用下列已核实规则，不声称已查看图片。无需重新访问原博客或联网搜索风格。

拼图从左到右、从上到下依次为：Claude Code CLI、FastAPI/Python 装饰器、Git 协作、HTML→Vite、n8n/WSL2/Docker、神经网络鞍点、opencode/Linux、Playwright 自动录制、Ubuntu/Mihomo、WebRTC 防护。

## 保持不变的风格

- **底色与主光：** 大面积近黑、午夜海军蓝背景，电蓝与青色为主光，少量冰蓝／白色高光；暗角、背景渐隐。可参考 `#030A16`、`#07162B`、`#008CFF`、`#25D9FF`，这些是近似指导色，不是取样得到的精确色值。
- **材质：** 深色玻璃、半透明亚克力、金属设备、全息界面或精细线框；边缘锐利、有厚度、适度反射。精致的 3D/2.5D 技术概念渲染，不是平面 PPT，也不是现实场景摄影。
- **光线：** 青蓝轮廓光、细光轨、局部柔和辉光，亮度集中在主体和关键连接点；保留暗部细节，不让整个画面被光晕淹没。可以有轻微体积光和景深。
- **构图：** 横向 16:9，清晰主次，中心或中部视觉焦点；左右模块、设备或概念通过流线、节点、箭头形成有意义的关系。背景面板低对比，缩略图仍能认出主体。
- **空间：** 常见悬浮主体、低位透视网格、环形光台、少量粒子波和电路线。按主题选用两三种即可，不把全部装饰塞进每张图。
- **色彩点缀：** 技术 logo 可保留原色，例如 Python 蓝黄、Git/Ubuntu 橙、n8n 粉；只占小面积，不改变蓝黑主调。主角可以是设备、软件标识、浏览器、盾牌或曲面，不是固定机器人。
- **文字：** 已有封面以短英文技术标签、命令或图标为主，没有大号中文文章标题。默认不把完整标题印入画面；建议 2–5 个短标签，必要时无字，使用清晰无衬线或等宽字体。用户明确要求中文标题或更多文字时允许覆盖此默认。

下列属于生成时的稳妥建议，而非声称所有旧图都符合：重要内容尽量留在画面中央约 80% 区域，四周留裁切余量；不把大量小字号代码或公式当作需要读懂的正文。

## 从文章到画面

1. 有正文或本地文件时先读标题、摘要和关键章节；只给标题时直接给合理方案，不要求补全整篇文章。完全没给主题才简短询问主题。不要根据标题擅自加入文章未提到的技术栈。
2. 提取一个核心对象、一条要解释的关系，以及少量必要辅助元素。先确定“画什么、为什么连起来”，再加风格。保持一致的是视觉语言，不是每篇都复用同一盾牌、服务器和圆环。
3. 选择最贴切的构图，不要机械混用：

| 内容类型 | 推荐画面语法 | 参考 |
| --- | --- | --- |
| 请求处理、编译、工具链 | 左侧输入 → 中央处理核心 → 右侧输出，亮线表现转换 | FastAPI、Vite |
| 部署、代理、远程开发 | 中央服务器／终端，客户端与服务在两侧，明确连接路径 | Ubuntu/Mihomo、opencode、n8n |
| 版本协作、流水线 | 横向节点链、分支及汇合，少量 logo 锚定起止 | Git 协作 |
| 自动化、浏览器操作 | 半透明浏览器为主，鼠标路径、录制信号或少量流程节点 | Playwright |
| 安全、隔离、防泄漏 | 盾牌／锁为焦点，让允许与阻断的数据流可区分 | WebRTC |
| 数学、模型、优化 | 银蓝半透明线框曲面、点云或几何关系，减少面板、logo 和霓虹饱和度 | 神经网络鞍点 |
| 非技术文章 | 选文章真正相关的概念隐喻，用同样的暗底、玻璃材质与蓝色光线呈现；不强塞代码和服务器 | 沿用材质与光线而非旧图对象 |

4. 技术语义优先：分支要能读出分叉／汇合；数据流方向与正文一致；不能把代理、自动化或 CI/CD 画成无关图标拼贴。数学表达只使用有把握的简单形式，不照抄参考图中可能不严谨的公式或标签。
5. 把构图、对象、位置、连接关系、材质、光线、文字白名单和画幅写进完整提示词；不要仅交付“高质量、科技感、8K”形容词列表。

## 输出

默认只给以下三部分，不附长篇风格分析或多个相近备选，除非用户要求：

**构图思路：** 一句中文说明文章主题如何变成画面。

**正向提示词：** 一个独立代码块，英文约 150–250 词（中文请求则改用中文），写成完整可执行描述。顺序可为：16:9 技术博客封面 → 主体与空间布局 → 数据／概念关系 → 深蓝黑配色与材质 → 局部灯光与背景层次 → 精确短标签 → 缩略图可读性和边缘余量。不要留下花括号占位符或让用户自行补词。

**负向约束：** 一个短代码块，按题材删减：

```text
bright white background, dominant pink or purple neon, cartoon or anime styling, flat clip-art, busy cyberpunk city, rainbow lighting, excessive bloom, blown-out highlights, cluttered interface panels, unreadable paragraphs, oversized headline, watermark, unrelated logos, meaningless connections
```

负向约束不能与正向内容冲突：允许 n8n 的少量粉色 logo，不允许粉紫色主导全图；允许 Linux 企鹅等原标识，不等于整图卡通化。用户要求大标题时移除对应排除项。目标工具没有负向提示字段时，将约束浓缩合入正向提示词末尾，不虚构模型参数。默认只写自然语言“16:9”，不擅加 `--ar`、`--stylize` 或种子等专属参数。

## 短示例：GitHub Actions 自动部署

用户只有这个标题时，画 GitHub 源码节点连接到居中的半透明工作流面板，再连接右侧部署完成的站点预览；面板中用少量节点表达构建与部署，青蓝光轨体现执行方向，成功状态只加微小绿色指示。背景是深蓝黑和低对比网格，面板有玻璃厚度及金属边框；标签可用 `GitHub`、`Build`、`Deploy`，不凭空指定 Docker、Kubernetes 或某个云厂商。正式交付时展开为完整提示词，不只返回这段构图摘要。

## 交付前核对

- 画面能从主体和连线看出文章主题，而非任意通用科技封面？
- 保留暗底、蓝青主光、立体／线框材质及清晰主次？数学分支是否更克制？
- 文字少而有用，技术语义没有被装饰或错误 logo 带偏？
- 输出是可直接使用的完整提示词，无未填模板和互相矛盾的约束？

本 skill 的默认产物仅为提示词：不调用图片生成服务、不花费额度、不修改文章或封面、不构建或发布博客。用户另外明确要求生成图片时再进入相应绘图流程；不要承诺仅靠提示词就能让不同模型的输出完全一致。参考图用于风格理解，不代表自动上传授权。
