# 第 7 层：诊断与恢复

**何时加载**: Audit、Prevent 模式；或 Skill 的错误处理不足时。

**核心问题**: Skill 能检测并修复自己的错误吗？失败时能优雅降级吗？

---

## 诊断问题

### 错误检测

1. Skill 是否有错误检测机制？（不是等用户发现，而是主动检查）
2. 错误检测是否覆盖了最常见的前 5 种失败模式？
3. 静默失败是否有检测方式？（输出看起来对但实际错——最危险的失败类型）
4. 是否有"健康检查"？（关键步骤完成后验证是否真的成功了）

### 错误分类

5. 是否区分了错误类型？（可自动修复 vs 需人工介入 vs 不可恢复）
6. 各类错误是否有对应的处理流程？
7. 错误信息是否包含诊断信息？（不只是 "失败了"，还要 "因为什么失败"）

**错误分类模板**:
| 类型 | 示例 | 处理方式 |
|------|------|---------|
| 可自动修复 | 依赖缺失、格式错误 | Agent 自动修复并继续 |
| 需人工介入 | 权限不足、认证过期 | 暂停并告诉用户怎么做 |
| 不可恢复 | 核心文件损坏、API 已废弃 | 保存已完成部分，报告情况 |

### 错误恢复

8. 可恢复错误是否有自动修复流程？
9. 修复是否被验证？（修复后重新跑失败的那一步，不是修了就当好了）
10. 是否有重试上限？（无限重试 = 资源黑洞）
11. 重试失败后是否有升级路径？（→ 更详细的诊断 → 人工介入）

### 故障排查

12. 是否有常见故障的排查指南？（至少覆盖 top 3 失败场景）
13. 排查指南是否给出了具体的诊断步骤？（不是 "检查一下错误"，而是 "运行 X 命令，确认 Y 值"）
14. 排查指南是否有分支逻辑？（"如果 X 则做 A，如果 Y 则做 B"）
15. 是否与 self-improvement Skill 集成？（记录 learnings 供未来参考）

### 降级路径

16. 是否有优雅降级路径？（A 方案不行 → B 方案 → 至少输出已完成的部分）
17. 降级方案是否仍能提供部分价值？（"无法生成完整报告，但这是已完成章节的摘要"）
18. 降级决策是否透明？（告诉用户降级了、为什么、丢失了什么）

### 学习与改进

19. 每次失败后是否有 learnings 记录机制？
20. 复发问题是否有追踪？（第 3 次出现同样错误 → 不是修复个案而是修复 Harness）
21. 是否有提升 learnings 为永久规则的机制？

**参考**: self-improvement Skill 的 LEARNINGS.md + ERRORS.md + 升级到 CLAUDE.md 的机制。

## 本层优秀模式

| 模式 | 来源 | 说明 |
|------|------|------|
| 错误分类 + 处理表 | 本 Skill | 可自动修复 / 需人工 / 不可恢复 |
| 排查分支指南 | — | "If X, do A. If Y, do B" |
| Learning 升级 | self-improvement | 复发问题从 .learnings/ 提升到 CLAUDE.md |
| 降级透明 | — | 降级时告诉用户丢失了什么 |

## 本层常见故障

1. **无错误模型**: 只考虑 happy path，异常即卡死（见 failure-patterns.md #9）
2. **静默失败**: 输出看起来对但实质错——最危险的失败
3. **无限重试**: 没有重试上限和升级路径
4. **不学习**: 同样错误反复出现，没有记录和改进机制

## 评分指南

| 评分 | 标准 |
|------|------|
| **Strong** | 有错误检测 + 分类处理 + 降级路径 + learnings 记录 + 升级机制 |
| **Adequate** | 有基本错误处理和降级路径 |
| **Weak** | 有错误意识但无系统化处理（每次靠 Agent 临时发挥） |
| **Missing** | 无错误处理，happy path only |
