# Learning-science patterns

用于把学习文档从“讲得懂”升级为“能诊断、能迁移、能复习”。按需读取，不要把所有模式机械塞进每次输出。

## Cognitive load control

学习文档不是信息越多越好。复杂主题必须分层，避免把定义、例子、公式、反例、边界塞进同一段。

默认分三层：

1. **30 秒版**：一句话本质 + 一个直觉类比。
2. **5 分钟版**：为什么出现 → 是什么 → 最小例子 → 适用边界。
3. **深度版**：完整推导/证明 → 反例 → 变式迁移 → 常见误区。

每节只解决一个核心问题。若用户出现“看不懂/太抽象/太多了”，立刻降低认知负荷：减少符号、缩小例子、先讲直觉、暂缓证明。

## Broad-topic output control

当主题是课程级大主题（如“数据挖掘”“概率论”“机器学习”“时间序列”）且用户选择“标准版”或“考试复习”时，不要一次写成小教材。优先输出“高频考试总览 + 知识地图 + 下一步模块选择”。

规则：

- 若考试范围不确定：明确写“以下按常见考试框架整理”，只覆盖最高频 5-7 个模块。
- 每个模块只写：核心问题、考试判断点、1 个最小例子、1 个常见误区。
- 不要展开所有算法、所有指标、所有计算细节；把细节列为“下一步可展开模块”。
- 练习题答案放在文末“参考答案”或简短折叠说明中，避免打断练习。
- 输出末尾用 AskUserQuestion 让用户选择下一步展开哪个模块：概念辨析 / 算法流程 / 指标计算 / 真题训练 / 错题整理。

如果用户明确要求“完整总览/越全越好/做成大纲文档”，可以加长，但仍要分层、分模块、避免单段堆砌。

## Difficulty tuning

根据用户诊断题和反馈调节难度。

- 前置知识缺失：降低抽象度，先补最小前置概念。
- 看得懂但不会用：增加例子判断和边界对比。
- 会做例题但不会迁移：增加交错练习和变式题。
- 诊断题全对：可以进入推导、证明、反例和边界。
- 连续表示没懂：换角度，并拆成更小台阶，不重复原话。

目标是“有挑战但不超载”。

## Prediction and pretesting

讲新概念前，优先用 AskUserQuestion 给 1-3 个小判断题或预测题。目的不是考试，而是暴露已有直觉、错误前概念和前置知识缺口。必须等待用户选择后再讲解；不要在正文里自问自答，也不要直接附“参考判断/参考答案”。

用户答错时，不要直接说“错”。先指出这个选项背后的直觉为什么合理，再解释它在哪个条件上失效。

## Misconception-first teaching

讲核心概念前，列出 2-4 个常见误解，让用户选择最接近自己的理解。很多学习困难不是空白，而是已有直觉不完整或部分错误。

常见误解类型：

- 把生活直觉当严格定义。
- 把充分条件当必要条件。
- 把检验工具当概念本身。
- 把特例当通用规则。
- 只记公式，不知道边界。

## Knowledge-state routing

根据用户回答选择讲解路线，不要所有人走同一套文档。

- 前置知识缺失：先补最小前置概念，再进入主题。
- 已有错误直觉：先做概念冲突，用反例纠偏。
- 会背定义但不会用：多给例子判断和边界对比。
- 会套公式但不会推导：重点讲“为什么想到这一步”。
- 能做例题但不会迁移：重点给变式、题型识别和条件变化。

## Worked example → faded example → transfer task

讲题或方法时，使用三段式：

1. **Worked example**：完整例题，每一步写明“做什么”和“为什么”。
2. **Faded example**：半填空例题，保留框架，挖掉关键步骤让用户补。
3. **Transfer task**：迁移题，换条件、换问法或换场景，让用户判断方法是否仍适用。

不要只给一个完整例题就结束；看懂例题不等于会迁移。

## Self-explanation prompts

在推导、证明和解题关键步骤后插入短提示：

```markdown
> 停一下：这一步为什么能这样做？
> 这里用了哪个定义/条件？
> 如果少了这个条件，这一步还成立吗？
```

提示要短，不要打断主线。目标是让用户主动加工，而不是被动看懂。

## Retrieval practice

文档末尾加入检索练习，而不是只给总结。检索练习要让用户闭卷回忆、区分边界、迁移应用。

```markdown
## 闭卷回忆
1. 不看上文，说出这个概念解决什么问题。
2. 写出推导/证明的主线，不必写每个细节。
3. 举一个适用例子和一个不适用例子。

## 边界判断
1. 场景 A 能不能用？为什么？
2. 场景 B 和正文例子差在哪里？

## 迁移练习
1. 如果条件换成 X，方法怎么变？
2. 如果目标换成 Y，突破口在哪里？
```

## Dual coding and concrete representation

抽象概念尽量同时给两种表示：

- 文字解释：说清逻辑。
- 表格/流程图/关系图描述：显示结构。
- 最小具体例子：把抽象落地。
- 对比表：区分相近概念和边界。

如果不能画图，也要用文字描述“图应该怎么看”。

## Metacognitive calibration

文档末尾加入“你真的懂了吗？”校准题，帮助用户区分“看着熟悉”和“真的掌握”。

```markdown
## 你真的懂了吗？

给自己打分：
1. 我能说出它解决什么问题吗？
2. 我能不用原文复述定义吗？
3. 我能解释一个反例吗？
4. 我能判断什么时候不能用吗？
5. 我能做一道变式题吗？

如果 0-2 分：回到直觉版和前置知识。
如果 3-4 分：做迁移题和边界判断。
如果 5 分：进入下一主题或更深推导。
```

## Spaced review plan

完整学习文档末尾加入简短复习安排。

```markdown
## 复习安排

- 10 分钟后：闭卷说出核心问题和一句话总结。
- 1 天后：重做检索练习。
- 3 天后：做迁移题或边界判断题。
- 7 天后：尝试教别人，并补一个反例。
```

## Interleaving practice

题型学习和方法学习要加入交错练习，训练“什么时候用”，不是只训练“知道题型后怎么做”。

```markdown
## 交错练习

1. 这题能直接用本方法。
2. 这题看起来能用，但其实条件不满足。
3. 这题需要先转化，才能用本方法。
```

## Error-cause labels

错题、题目讲解、概念纠偏时给出错因标签。不要只说答案错，要说明错在知识结构哪一层。

可用标签：

- 概念误解
- 前置知识缺口
- 条件漏读
- 公式套用
- 边界不清
- 题型误判
- 推导跳步
- 计算错误
- 迁移失败
