# 领域适配器

同一套系统规划框架要根据目标类型调整重点。不要把学习计划写成项目排期，也不要把项目计划写成学习打卡。

## 1. 适配器选择规则

先根据用户表达判断领域：

| 用户意图 | 使用适配器 |
|---|---|
| 学一门课、掌握技能、建立知识体系 | 学习项目适配器 |
| 考研、考试、备考、提分 | 考试/考研适配器 |
| 做产品、软件、工作任务、内容项目 | 工作/项目适配器 |
| 形成能力，如写作、编程、表达、销售 | 能力建设适配器 |
| 把方法论做成 Claude Code skill | Skill 设计适配器 |
| 同时包含学习、考试、项目 | 混合型适配器 |

如果不确定，先判断最终验收标准：

```text
分数导向 → 考试/考研
掌握知识导向 → 学习
交付成果导向 → 项目
长期表现导向 → 能力
可复用流程导向 → Skill 设计
```

## 2. 学习项目适配器

适用于：学习统计学、Python、英语、写作、经济学、AI 工具等。

### 规划重点

- 知识框架：先知道整体地图。
- 主动提取：不能只看书、看课。
- 练习反馈：通过题目、案例、输出暴露问题。
- 间隔复习：安排 D1、D3、D7 复测。
- 应用输出：用作品、讲解、项目检验掌握程度。

### 必须包含

```text
1. 学习目标和可测标准。
2. 当前基础和薄弱点。
3. 学习材料和练习材料。
4. 输入 → 提取 → 练习 → 反馈 → 复习的闭环。
5. 每周输出物。
6. 间隔复习安排。
```

### 常见错误

- 只安排“看课”“看书”。
- 笔记太多，练习太少。
- 没有闭卷复述或自测。
- 没有复习间隔。
- 没有可验证输出。

### 推荐结构

```text
目标 → 当前基础 → 知识模块 → 阶段计划 → 本周学习任务 → 日学习动作 → 复习系统 → 作品/输出 → 复盘
```

### 动作级任务例子

```text
坏：学习统计学。
好：完成《统计学》第 3 章抽样分布，闭卷写出中心极限定理解释，并完成 20 道基础题，记录错因。

坏：看 Python 视频。
好：看完函数章节后，不看教程写出 3 个函数练习，并把错误记录到练习日志。
```

## 3. 考试 / 考研适配器

适用于：考研、英语考试、资格证、期末考试等。考研场景优先使用这个适配器。

### 规划重点

- 分数目标：总分和单科目标。
- 科目拆解：每科当前水平、目标水平、提分瓶颈。
- 真题系统：真题年份、题型、二刷/三刷安排。
- 错题系统：错因分类、复测、二次正确率。
- 背诵系统：新背、复背、默写、抽查。
- 模考系统：时间分配、稳定性、临场策略。
- 阶段推进：基础、强化、提高、冲刺。

### 必须包含

```text
1. 目标院校/专业或考试名称。
2. 考试科目和目标分数。
3. 当前基础或最近测试表现。
4. 每科阶段任务。
5. 真题安排。
6. 错题复盘规则。
7. 背诵和复测规则。
8. 模考安排。
9. 每周复盘。
10. 最低保底任务。
```

### 阶段建议

```text
基础阶段：补概念、补框架、完成基础题。
强化阶段：专题训练、真题入手、错题分类。
提高阶段：套卷训练、速度训练、背诵强化。
冲刺阶段：模考、查漏补缺、稳定输出。
```

### 科目处理规则

#### 英语

- 单词要每日持续，但不能占用全部时间。
- 阅读真题是主线。
- 作文要形成模板、积累句型，并定期手写。
- 错误要分类：词汇、长难句、定位、推理、选项陷阱。

#### 政治

- 前期理解框架，中后期强化选择题和背诵。
- 背诵必须配合默写或口述。
- 模拟卷用于查漏，不要只追求刷数量。

#### 数学

- 概念、题型、计算、速度都要训练。
- 错题必须复做，不能只看答案。
- 定期做套卷训练时间分配。

#### 专业课

- 建立章节框架。
- 高频考点优先。
- 背诵材料要转成问题清单。
- 用真题反推重点。

### 动作级任务例子

```text
坏：复习英语阅读。
好：完成 2018 英语一 Text 2，限时 18 分钟；精读全文；记录 5 个错因或长难句；3 天后重做错题。

坏：背专业课。
好：闭卷默写专业课第 4 章一级标题和 6 个核心概念，错漏处标红，晚上复述一遍。
```

## 4. 工作 / 项目适配器

适用于：软件开发、产品设计、运营活动、内容项目、内部工作任务。

### 规划重点

- 交付物：最后要交什么，不是做了什么。
- 验收标准：怎样算完成。
- 范围边界：本次做什么、不做什么。
- 依赖关系：谁或什么会阻塞。
- 里程碑：中途检查点。
- 风险和缓冲：估时错误、需求变化、外部依赖。
- 最小可交付版本：时间不够时保留核心。

### 必须包含

```text
1. 项目目标。
2. 范围边界。
3. 交付物列表。
4. 验收标准。
5. 里程碑。
6. 任务依赖。
7. 风险与应对。
8. 本周/今日动作。
9. 最低可交付版本。
```

### 推荐结构

```text
目标 → 边界 → 交付物 → 里程碑 → 任务依赖 → 风险 → 本周执行 → 检查点 → 交付验收
```

### 常见错误

- 把“研究一下”“优化一下”当任务，没有交付物。
- 没写不做什么，导致范围膨胀。
- 没有验收标准，导致做完也不知道是否完成。
- 忽视外部依赖。
- 没有最小版本。

### 动作级任务例子

```text
坏：优化首页。
好：列出首页首屏 3 个主要问题，完成新版信息架构草图，并用 5 条检查标准验收。

坏：做一个脚本。
好：实现读取 CSV、清洗字段、导出 JSON 的最小脚本，并用 3 个样例文件测试通过。
```

## 5. 能力建设适配器

适用于：写作能力、编程能力、表达能力、销售能力、研究能力等长期能力。

### 规划重点

- 能力不是靠时长证明，而靠稳定表现证明。
- 必须定义练习场景和反馈来源。
- 要有作品或表现记录。
- 训练要分解为子能力。
- 周期要长，但近期行动要具体。

### 必须包含

```text
1. 目标能力定义。
2. 子能力拆解。
3. 练习场景。
4. 反馈来源。
5. 作品/表现记录。
6. 周期性复盘。
```

### 推荐结构

```text
能力目标 → 子能力 → 练习任务 → 反馈机制 → 作品记录 → 阶段评估 → 下一轮训练
```

### 动作级任务例子

```text
坏：提升写作能力。
好：本周写 3 篇 800 字观点短文，每篇只训练“开头提出清晰判断”，写完用 5 项清单自评并修改一版。
```

## 6. Skill 设计适配器

适用于：用户想把方法论、流程、经验、提示词做成 Claude Code skill。

### 规划重点

- 触发条件：什么时候用。
- 排除条件：什么时候不用。
- 输入字段：需要哪些信息。
- 澄清问题：最多问几个，什么情况下问。
- 工作流：内部步骤。
- 参考文件：大内容放 references，入口保持简洁。
- 输出格式：默认结构。
- 质量检查：防止输出漂移。
- 失败模式：触发过宽、问太多、输出空泛、引用过重。

### 必须包含

```text
1. skill 名称。
2. 使用场景。
3. 不使用场景。
4. 主工作流。
5. references 文件设计。
6. 输出模板。
7. 质量检查。
8. 测试句。
```

### 文件结构建议

```text
<skill-name>/
├── SKILL.md
└── references/
    ├── framework.md
    ├── templates.md
    ├── examples.md
    └── checklist.md
```

不是所有 skill 都需要 references。只有当规则、模板、案例较多时才拆分。

### SKILL.md 内容建议

```text
1. frontmatter：name 和 description。
2. 用途。
3. 什么时候使用。
4. 什么时候不要使用。
5. 核心工作流。
6. 参考文件读取规则。
7. 输出格式。
8. 质量要求。
9. 风格要求。
```

### 常见错误

- description 写得太窄，导致不会触发。
- description 写得太宽，导致无关任务也触发。
- SKILL.md 太长，塞入所有理论和模板。
- 没有排除条件。
- 没有测试句。
- 只写提示词，不写工作流和质量检查。

## 7. 混合型适配器

适用于目标同时包含多个性质，例如：

- “三个月学 Python 并做出一个数据分析项目”
- “考研同时准备作品集”
- “学一套方法并做成 skill”

### 处理规则

1. 先确定最终验收标准。
2. 把目标拆成 2–3 条主线。
3. 每条主线使用对应适配器。
4. 不要让所有主线同等重要；必须排序。
5. 每周只保留 1 个最高优先级。

### 输出结构

```text
总目标 → 主线拆解 → 优先级 → 分阶段计划 → 本周最高优先级 → 每条主线任务 → 风险与取舍 → 复盘
```

### 取舍规则

如果时间不够，按以下顺序保留：

```text
1. 直接影响最终验收的任务。
2. 会产生复利的基础任务。
3. 能暴露问题的反馈任务。
4. 低价值整理、美化、资料囤积最后做。
```

## 8. 适配器输出前检查

生成最终计划前确认：

```text
- 是否选对了目标类型？
- 是否用了该领域真正重要的指标？
- 是否避免了该领域常见假努力？
- 是否给出动作级任务？
- 是否包含反馈和复盘？
- 是否能在 24 小时内开始？
```
