# 质量检查清单

这个文件用于输出前自查。不要把完整清单原样输出给用户，除非用户要求；默认在内部使用，并在必要时简短说明关键假设和风险。

## 1. 最低合格标准

一个合格计划必须回答：

```text
1. 我要达成什么？
2. 什么时候达成？
3. 怎么判断达成？
4. 当前现实条件是什么？
5. 最终成果拆成哪些部分？
6. 分几个阶段推进？
7. 本周做什么？
8. 今天或 24 小时内做什么？
9. 如果失败或被打断怎么办？
10. 什么时候复盘和调整？
```

如果以上问题有 3 个以上没有答案，计划不合格。

## 2. 通用质量检查

输出前逐项检查：

```text
[ ] 目标是否具体？
[ ] 是否有截止时间？
[ ] 是否有可衡量标准？
[ ] 是否说明了目标用途或价值？
[ ] 是否分析了当前状态？
[ ] 是否列出可用时间、资源、限制条件？
[ ] 是否识别主要风险？
[ ] 是否先拆成果，再排任务？
[ ] 是否有 3–5 个阶段？
[ ] 每个阶段是否有产出和验收标准？
[ ] 本周计划是否具体？
[ ] 日任务是否是动作级？
[ ] 是否有最低保底任务？
[ ] 是否有缓冲，而不是把时间排满？
[ ] 是否有 if-then 应对方案？
[ ] 是否有每周复盘机制？
[ ] 用户是否知道接下来 24 小时该做什么？
```

## 3. 目标质量检查

### 不合格目标

```text
我要努力学习。
我要提升能力。
我要准备考研。
我要把项目做好。
```

问题：没有截止时间、没有结果、没有标准。

### 合格目标

```text
我想在 8 周内完成统计学基础学习，能独立解释 12 个核心概念，完成 200 道基础题并把错题复测正确率提升到 80% 以上。
```

检查规则：

```text
[ ] 是否包含时间？
[ ] 是否包含具体结果？
[ ] 是否包含可衡量标准？
[ ] 是否符合现实约束？
```

## 4. 任务质量检查

### 不合格任务

```text
学英语。
看数学。
做项目。
背专业课。
整理资料。
```

问题：动作不清、完成标准不清、无法复盘。

### 合格任务

```text
限时 18 分钟完成 2019 英语一 Text 1，精读后记录 3 个错因，并在 3 天后重做错题。
```

检查规则：

```text
[ ] 是否有明确动作？
[ ] 是否有对象或材料？
[ ] 是否有数量或时间？
[ ] 是否有完成标准？
[ ] 是否能被复盘？
```

## 5. 学习计划专项检查

学习计划必须避免“只输入不输出”。

```text
[ ] 是否有知识框架？
[ ] 是否有主动提取练习？
[ ] 是否有做题、案例、项目或输出？
[ ] 是否有间隔复习？
[ ] 是否有错题或错误记录？
[ ] 是否有反馈来源？
[ ] 是否避免只写看课、看书、整理笔记？
[ ] 是否有周复盘，判断策略是否有效？
```

如果学习计划里没有提取练习和间隔复习，必须补充。

## 6. 考研 / 考试计划专项检查

考研计划必须围绕分数、真题、错题、背诵、模考。

```text
[ ] 是否写明目标院校/专业或考试名称？
[ ] 是否写明考试科目？
[ ] 是否有目标分数或表现标准？
[ ] 是否分析每科当前水平？
[ ] 是否有真题安排？
[ ] 是否有错题系统？
[ ] 是否有背诵系统？
[ ] 是否有模考安排？
[ ] 是否有每科优先级？
[ ] 是否有冲刺阶段的查漏补缺机制？
[ ] 是否有最低保底任务？
```

如果用户没有提供目标院校、科目、当前基础，可以先基于假设输出初版，但要明确标注假设。

## 7. 工作 / 项目计划专项检查

项目计划必须围绕交付物和验收标准。

```text
[ ] 是否明确最终交付物？
[ ] 是否写明本次范围和不做范围？
[ ] 是否有验收标准？
[ ] 是否有里程碑？
[ ] 是否识别依赖关系？
[ ] 是否识别风险？
[ ] 是否有最小可交付版本？
[ ] 是否安排检查点？
[ ] 是否避免把“研究一下”“优化一下”当成最终任务？
```

如果没有交付物，项目计划不合格。

## 8. Skill 设计计划专项检查

Skill 设计计划必须围绕触发、流程、文件结构和质量控制。

```text
[ ] 是否有 skill 名称？
[ ] 是否有清晰 description 方向？
[ ] 是否写明什么时候使用？
[ ] 是否写明什么时候不要使用？
[ ] 是否有核心工作流？
[ ] 是否定义澄清问题规则？
[ ] 是否设计 references 文件？
[ ] 是否有输出格式？
[ ] 是否有质量检查？
[ ] 是否有失败模式？
[ ] 是否有测试句？
```

如果 skill 只是一个长提示词，没有触发条件、工作流和质量检查，需要重写。

## 9. 风险与缓冲检查

计划必须承认现实波动。

```text
[ ] 是否考虑估时低估？
[ ] 是否给新任务、难任务加缓冲？
[ ] 是否每天只安排 70%–80% 可用时间？
[ ] 是否有最低保底任务？
[ ] 是否有被打断后的恢复方案？
[ ] 是否有状态差时的降级方案？
[ ] 是否有信息过载时的取舍规则？
```

推荐补救语句：

```text
如果当天计划被打断，只保留最高价值任务和最低保底任务，不补低价值整理任务。
```

## 10. if-then 检查

容易失败的地方必须写 if-then。

```text
[ ] 拖延时怎么办？
[ ] 起晚时怎么办？
[ ] 被临时任务打断怎么办？
[ ] 状态差怎么办？
[ ] 任务超时怎么办？
[ ] 提前完成怎么办？
```

格式：

```text
如果【具体情况】发生，我就【具体行动】。
```

不要写：

```text
如果拖延，就提高自律。
```

要写：

```text
如果晚上 8 点还没有开始，我就只做 25 分钟最低保底任务，并把手机放到另一个房间。
```

## 11. 复盘机制检查

没有复盘的计划只是日程表。

```text
[ ] 是否指定复盘频率？
[ ] 是否有复盘问题？
[ ] 是否比较计划与实际？
[ ] 是否检查估时偏差？
[ ] 是否检查任务价值？
[ ] 是否决定下周保留、删除、加强什么？
```

周复盘至少回答：

```text
1. 本周原计划是什么？
2. 实际完成了什么？
3. 哪些任务低估了耗时？
4. 哪些任务最有效？
5. 哪些任务应删除？
6. 下周保留、删除、加强什么？
```

## 12. 输出风格检查

```text
[ ] 是否使用中文，除非用户要求英文？
[ ] 是否避免空泛励志？
[ ] 是否避免堆太多选项？
[ ] 是否给出推荐方案？
[ ] 是否明确假设？
[ ] 是否没有把计划排满？
[ ] 是否没有输出过长的理论解释？
[ ] 是否能让用户马上行动？
```

不推荐：

```text
你要保持热情，坚持到底，相信自己。
```

推荐：

```text
今天只做三件事：整理当前进度、完成第一组 25 分钟任务、记录一个错因。先让系统跑起来，再优化强度。
```

## 13. 最终快速检查

输出前用 10 秒做快速判断：

```text
1. 用户能不能看懂？
2. 用户能不能今天开始？
3. 用户能不能知道完成标准？
4. 用户失败后有没有补救动作？
5. 下周能不能根据复盘调整？
```

如果任一答案是否定，修改后再输出。
